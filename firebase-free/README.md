# 無料版の導入と運用

GitHub Pages + Cloud Firestoreを使用します。課金プランへの変更、外部APIキー、オンライン決済は不要です。既存Realtime Databaseの会計・名簿は変更しません。Firestoreの無料枠を超えると利用が停止するため、運営前にコンソールで使用量を確認してください。

## 本番設定（ログイン・合言葉・承認なしの公開合宿一覧）

利用者の指定により、誰でも `camps.html` を開いて合宿の一覧を取得し、参加者・出欠・行程・見積・入金・決算を閲覧・編集できる方式です。Googleログイン・匿名認証・端末承認・共有リンク入力は不要。共有リンクも従来どおり使えます。

**公開リスク：合宿一覧が表示されると各合宿のIDも第三者にわかり、団員名・参加状況だけでなく個人別の請求額・入金額・未納額・会計取引を閲覧・改変できます。** 合宿の非表示（アーカイブ）はアクセス制限ではありません。誰が編集したか確実な本人確認もできません。検索エンジン向けの `noindex` はアクセス制限になりません。個人の金融・健康・緊急連絡先・所在などの情報は登録しないでください。既存の入力情報も公開対象になるため、Firebase管理者は公開前に現状データを点検してください。

1. Firestore Standardが使用可能であることをFirebaseコンソールで確認します（既存プロジェクトは東京リージョンで準備済み）。
2. Firebase Console → Firestore Database → Rulesで**現在の本番ルールをバックアップ**し、`firebase-free/firestore.rules` と差分を比較します。必要な変更は基本的に`campShared/{c}`の`allow list`で、`request.query.limit != null && request.query.limit <= 100`へ変更します。その他のコレクション・データ・アクセス制御を無条件に公開しないでください。
3. 内容を確認してFirestoreルールを公開します。GitHub Pagesのコード公開だけでは本番ルールは切り替わりません。
4. `camps.html` をiPhoneのSafari/LINE内ブラウザで開き、承認や合言葉なしで既存の合宿が一覧に出ることを確認します。合宿データの新規作成・変更は既存の競合チェックと安全なフィールド許可ルールのままです。

全合宿の直接取得は新しい開催日順に最大100件です。端末に以前開いた合宿のIDが残っていれば、一覧取得に失敗しても既知の合宿の照会を試みます。古い`campDirectoryReaders`・`campDirectoryRequests`のデータは自動削除せず、これらの領域の非公開ルールは維持します。旧端末承認機能は使用しません。

## 検証

`npm test` は既存機能、`npm run test:camp:free` は無料版の計算テストです。ルールとブラウザの結合テストは本番データを使わず、プロジェクトID `demo-smc-camp` のFirestoreエミュレーター（127.0.0.1:8085）で実行します。

開発時のQA依存はリポジトリ隣の `../qa` に `firebase`, `@firebase/rules-unit-testing`, `playwright` をインストールします。Java21とFirebase Firestoreエミュレーターを起動し、`node scripts/camp-free-rules.test.mjs`、続いて `node scripts/camp-free-browser.test.mjs` を実行します。QA依存を別の場所へ入れた場合は、`CAMP_QA_PACKAGE` にその `package.json` の絶対パスを指定します。`firebase-*-compat.js` は同じフォルダへ置いてください。Playwrightだけ別の場所にある場合は `PLAYWRIGHT_MODULE` を、画像・PDFの出力先を変える場合は `CAMP_QA_OUTPUT` を指定します。ブラウザテストは前者が作成するテストデータを利用します。匿名・未ログイン状態の読み書きを検証します。本番疎通は別途確認してください。

## 合宿のクラウド保存（運用対象）

`camps.html`は合宿情報・参加者・行程・会計をCloud Firestoreの`campShared`に保存し、サーバーからの再読込後に保存成功を表示します。誰でもログインや端末申請なしで、クラウドの合宿一覧を直接開いて編集できます。別ブラウザ・別端末でも同じ合宿にアクセスできます。配車・部屋割り・点呼機能は削除済みで、過去の端末内記録は自動削除しません。

公開一覧のルールが本番で未適用の間は一覧取得時に権限エラーとなります。接続エラーを成功扱いせず、Firebase Consoleの現在のルールを確認してください。既存Realtime Databaseおよび会計台帳のデータ構造は変更しません。

## バックアップ・復旧

利用者は設定画面からJSONバックアップを保存し、アクセス制限した団の保管先へ保存してください。決算CSVも併せて保管します。自動バックアップ・ワンクリック復元は未実装です。復旧時は元データを保全したうえで、開発担当が別のテスト合宿へ復元し、請求・入金・返金・収支と権限を照合してから本番へ反映してください。単純な上書きは避けてください。

通信切断時の編集キューはありません。未保存入力は同じ画面内で保持し、再接続後に保存します。競合はrevisionで拒否し、入金再送は操作IDで二重登録を防ぎます。サーバールールは保存範囲・同時更新・公開台帳との同時保存を検証しますが、複雑な会計計算そのものはクライアントで実施します。

`camps-api.html`と`camp-server`は別方式の旧API版で、無料版の運用には使用しません。旧Render配置案は採用しません。保護者向け操作手順は `camp-free-guide.html` を参照してください。

## 合宿予算書の追加設定（2026-10-23）

新しい予算書は、既存の `budgets` と台帳を変更せず、次の追加領域を使います。

- `campShared/{id}/budgetLines/{rowId}`：収支区分・費目・対象・単価・数量・人数参照元・補足
- `campShared/{id}/private/budgetSettings`：参考参加費の切り上げ単位
- `campShared/{id}/settlementDrafts/{sourceKey}`：コピー時点の予算、元のID・revision、確認済み0円の状態
- 台帳の請求／入出金には任意の `budgetId` を付けて比較対象に紐づけます。金額を複製した取引は作りません。

公開順序は「エミュレーター検査 → このフォルダの `firestore.rules` を既存ルールと照合して反映 → アプリ公開」です。既存の他の許可領域を削除しないでください。コンソールでルールを貼り替える前に、現在のルールを保存してください。

追加ルールを未反映の環境では、機能検知の読み取りが拒否され、新しい予算書を有効にしません。従来の予算・集金決算はそのまま利用できます。画面に「新しい予算書は準備中」と表示された場合は、Firestoreコンソール → ルールで、検査済みルールの追加領域を反映して「公開」し、合宿の「最新情報を取得」を押してください。画面コードだけの公開では新しい保存領域を有効にできません。

コピーは選択した元予算と既存下書きをトランザクション内で再確認します。同じ元IDの下書きは1つだけです。再送時に同じ元revisionが反映済みなら追加更新しません。変更済み予算の再コピーは明示的な選択が必要です。実績台帳はコピー対象外です。

バックアップJSONには予算書・決算下書き・旧予算・台帳を含みます。ワンクリック復元機能はありません。復旧は別のテスト合宿で検証してから行ってください。

追加検証：`node scripts/camp-budget-compat.test.mjs` は、エミュレーター上で旧ルールの場合の安全な無効化と既存会計の継続を確認します。本番には接続しません。ブラウザ実行ファイルを別途用意した場合は `CAMP_QA_BROWSER` に絶対パスを指定できます。

## 参加区分・宿泊単位の料金拡張（2026-10-23）

- 既存の団員／大人一括料金は維持し、保護者・コーチ・その他参加者の参加費区分を追加します。
- 参加者の `kind` は既存の `player/parent/coach/other` を参照します。参加確定者と宿泊者を区分ごとに数えます。
- 予算と決算下書きに任意の `basis`（person/room/fixed）・`multiplier`（1〜100の泊数／回数）を追加します。旧行は1人単価・倍率1として読み、移行書込みはしません。部屋数は名簿から推定せず手入力です。
- 参加費は合宿全体の1人分です。泊数による参加費の二重計上は拒否します。宿泊料金は宿の料金区分・部屋タイプごとに行を分け、食事込み等を補足に記録します。
- 団費・プール金・寄付などは `income` の複数行で管理し、対象別・交通費限定の援助を対象外へ自動配分しません。予定／確定／入金済みの根拠は補足と実績台帳で区別します。補助の予定だけでは台帳入金は作りません。
- `campShared/{id}/private/budgetRates` は読取可否で新ルールを検知する予約文書です。作成・更新・列挙・削除は拒否し、検知時にもデータは書きません。新ルールがない場合は旧予算だけを編集でき、拡張入力欄を出しません。
- 同じ共有リンク方式を維持し、既存Realtime Database・参加者・台帳の保存構造は変えません。GPSの保存領域を許可する変更は含みません。

公開時は現在の本番Firestoreルールを必ず保全・比較し、この拡張だけを反映してください。現時点で本番へのルール公開はGoogle本人確認待ちです。

## 特別収支と管理者記録（2026-10-23）

一般向け画面は引き続きログイン不要です。正式制度名・加入申請根拠・対象者・支払者・受給者・了承記録は、共有リンク側に保存しません。管理者画面 `camp-special-admin.html#合宿UUID` だけがFirebase Authenticationと合宿別ACLで非公開記録を読み書きします。

### 追加保存先

| 保存先 | 内容 | 権限 |
|---|---|---|
| `campShared/{id}/specialBook/current` | 公開用金融項目だけの投影、配分、revision | 共有リンク利用者は取得のみ。書込みは認証・承認済み管理者 |
| `campSpecialPrivate/{id}/items/{itemId}` | 明細原本、非公開の確認記録、操作番号 | 合宿別ACLで承認済み管理者のみ |
| `campSpecialPrivate/{id}/history/{historyId}` | 変更前・後、操作元、更新日時 | 同上。追記のみ。変更・削除を拒否 |
| `campSpecialAdmins/{uid}` | `enabled: true` と `camps: {合宿UUID: true}` | 自分の権限設定の取得のみ。クライアントからの列挙・変更を拒否 |

管理者権限は画面のフラグや端末識別子で代用しません。Firebase管理者がコンソールで対象UIDと対象合宿を設定します。他の合宿は許可されません。Firebase AuthenticationでGoogleプロバイダーと公開ホストの認証ドメインを設定する必要があります。新しい役割設定はこの追加機能に限定し、既存Realtime Databaseの名簿・会計・一般向け合宿フローは変更しません。

### 本番設定と初期登録

1. 現在のFirestoreルールを保全し、検査済みの `firestore.rules` と差分を比較して追加領域を公開します。無関係な許可領域を消さないでください。
2. 管理者画面でGoogleログインし、表示されたFirebase UIDを確認します。Firebase管理者が `campSpecialAdmins/{uid}` に `enabled: true` と `camps` マップ内の対象合宿UUID: trueを設定します。自己登録や全員管理者化はしません。
3. 「最新情報を取得」で管理者記録へ入ります。2027-03-13〜14、名称に「春」を含む合宿だけに「春合宿の初期明細を登録」を表示します。対象名を確認して実行します。合宿IDを推測して登録しません。
4. 初期明細は固定ID `spring-2027-expense` / `spring-2027-aid`。既存の同IDは上書き・復活させず、不足分だけ追加します。補助利用関連費3×6200=18600、宿泊費補助3000×20=60000、差引41400です。団体帰属を仮定する予算上の試算として登録し、資格・帰属は要確認、入出金は作成しません。

本番のGoogle本人確認、認証プロバイダー、管理者UID・対象合宿IDの登録は未確認です。設定完了や実際の春合宿への初期データ登録を、コード公開だけで完了扱いにしないでください。テストは `demo-smc-camp` のエミュレーターに限定します。

### 計算と重複防止

- 通常予算は元の保存先のままです。特別収支の予定額を、通常の予算行や決算下書きへ複製しません。集計・PDF時に一度だけ合算します。予算は予定額、確定額は別の確認情報、実績は実際の台帳または値引き記録です。
- 個人受給は自動的に団体収入へ入れません。団体への充当を明示し、了承と資金移動予定を記録します。実績入金には適用資格・帰属・了承の確認と実際の台帳記録が必要です。
- 後日入金は入金実績だけを台帳へ登録します。既存の台帳記録を使う場合は参照だけを付け、取引を増やしません。既に対応づけた取引の再利用を拒否します。操作番号の再送は同じ内容なら1回だけです。
- 直接値引きは宿泊費の参照ID・revision・金額・値引き前／後を保持します。値引き前の場合のみ控除し、値引き後なら追加控除しません。宿泊費の変更・取消・過大控除・混在は再確認とし、値引きを入金として記録しません。
- 値引き実績は適用識別番号のSHA-256を公開投影に置き、原文は管理者記録だけに置きます。同一の適用識別番号を複数の明細へ登録できません。誤った適用は理由付きで「値引き実績を取消」できます。台帳は自動変更しません。
- 明細の取消は予定の集計から外す論理取消です。実際の入出金・値引きは消しません。台帳側の取消、または値引き実績の取消を別途明示します。金額・取消・実績・配分の履歴は管理者領域に保持します。
- 配分の合計は差引以下に制限します。明細の更新で配分を未確定へ戻します。配分だけで請求・入出金は作成しません。参加費の参考計算には確定した団員向け配分のみ反映します。実際の請求額は確認して別途設定します。
- 宿泊比較は子20・大人10、通常客室1泊の比較用試算です。山楽荘271000−60000+18600=229600、とどろき298500−60000+18600=257100。大部屋の人数・単価も変更できます。比較画面を変更しても予算原本へ書き戻しません。

公開用投影は金融フィールドの許可リストをサーバールールで検証します。一般向け読込・JSONバックアップ・CSV・PDFに非公開記録を含めません。管理者の変更履歴は一般向け印刷からも除外します。Google認証はセッション内とし、Firestoreの永続オフラインキャッシュは有効化しません。複雑な金額計算は既存会計同様クライアントで行い、権限・原本／公開投影／履歴の同時保存はサーバールールで検証します。

検査：`node --test scripts/camp-special.test.mjs`（CIに含む）、`node scripts/camp-special-rules.test.mjs`、`node scripts/camp-special-browser.test.mjs`。後二つは既存QA依存とFirestoreエミュレーターが必要です。

## 運用変更：特別収支も共有リンクで編集（2026-10-23）

利用者の最新指定により、通常の特別収支編集は `camp-special.html#合宿UUID` です。Google認証・管理者権限付与は不要です。上記の管理者設定手順は旧互換ページだけに該当し、新規にACLを付与しないでください。

共有保存先は `campShared/{id}/specialItems/{itemId}` と追記専用 `specialHistory/{historyId}`、集計は既存 `specialBook/current` です。原本・集計・履歴を同一トランザクションで保存します。端末識別子は本人認証ではありません。操作署名はSHA-256だけを保存し、非公開detailsは空欄のみをルールで許可します。個人名・制度名・対象者などを共有項目名へ入力しないでください。既存 `campSpecialPrivate` は公開せず、そこに紐づく明細の上書きも拒否します。

合宿のアーカイブは通常一覧から除外します。「非表示にした合宿」の表示欄は利用者の希望で撤去しました。アーカイブ済み合宿を再表示したい場合は、その合宿の共有URL（UUIDを含むリンク）で直接開き、合宿情報の「合宿を一覧から非表示」チェックを外してください。物理削除はせず参加者・会計など関連データを保全します。

追加検査：`scripts/camp-shared-special-rules.test.mjs`、`scripts/camp-shared-special-browser.test.mjs`。未認証2端末の編集・再読込・競合・非公開領域拒否・履歴保護・配分・PDF・5幅と両テーマ・非表示と復元導線を検査します。
