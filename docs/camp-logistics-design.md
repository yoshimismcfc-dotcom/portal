# 合宿の配車・部屋割り・手動点呼（端末内機能）

## 現行実装

- 入口：無料版合宿 `camps.html` → 合宿 → `配車・点呼`
- 計算：`camp/logistics-local-model.mjs`
- 画面：`camp/logistics-local-ui.mjs`
- 保存：`localStorage["smc-camp-operations-local-v1:"+campId]` のみ
- 参加者：すでに読み込んだ `camp.participants` の参加確定者を参照し、名前・学年を複製しない
- 車：表示名（例：1号車）、定員（運転者を含む）、運転者の既存参加者ID、利用可否
- 部屋：表示名（例：A室）、定員、利用可否
- 割当：既存参加者IDと車・部屋の内部ID。宿泊なしの人には部屋を割り当てない
- 点呼：出発・到着それぞれ手動で確認。位置情報・現在地の共有リンク・時刻・健康情報・緊急連絡先は保存しない
- ブラウザからローカル保存に失敗したときは成功と表示しない
- 車・部屋の超過はブロック。定員を減らす編集でも超過をブロック。運転者の二重計上を避ける
- 不参加になった人の古い割当は勝手に削除しない。「整理する」で明示処理
- 点呼全解除は確認ダイアログを経由
- Firestore/Realtime Database・権限ルール・合宿会計台帳は変更しない

## 安全性と限界

現行の合宿共有URLはログイン不要で、リンクを知る人は既存の参加者や会計を閲覧・編集できます。この権限形態のままで子どもの乗車先・部屋・所在確認記録をクラウド同期しません。端末内データは当該ブラウザにアクセスできる人からは見えるため、画面ロック等は利用者が管理してください。

iOSのSafari、ホーム画面PWA、LINE内ブラウザは別々の保存領域になることがあるため、端末変更やアプリ再インストールに対する復旧機能はありません。共有・永続バックアップは認証と役割別制御が準備されるまで実装しません。

GPS追跡、個人の位置共有リンク保存、全車の地図表示はしません。既存「ルート」内の外部Googleマップ手順を使い、共有先と期間は本人が制御します。

## 確認

`npm run test:camp:free` に `scripts/camp-logistics-local.test.mjs` を追加。モデルの保存・区分・定員・点呼・上限・操作失敗を確認します。iPhone Safari実機やLINE内ブラウザでの端末領域・画面配置は別途点検してください。
