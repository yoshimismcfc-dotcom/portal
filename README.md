# 吉見SMC FC スマートポータル

吉見SMCサッカースポーツ少年団の連絡・出欠・試合・当番・名簿・会計をまとめる、静的HTML中心のWebアプリです。GitHub Pagesでの配信を想定し、Firebase Realtime Databaseと端末内ストレージを併用します。

## 主な構成

- `index.html` — ホーム
- `common.css` / `common.js` — 共通デザイン、テーマ、PWA登録、印刷、保存通知、端末内エラーログ
- `firebase-config.js` — Firebase初期化、リアルタイム読込、保存結果の共通処理
- `sw.js` / `manifest.json` / `offline.html` — PWAと一部オフライン表示
- `members.html` / `staff.html` — 団員名簿・担当者
- `game_adjust.html` / `tournament.html` / `duty_match.html` — 試合調整・大会資料・当番
- `tournament-scheduler.js` — 対戦カードの重複を防ぎ、連続試合と休憩偏りを減らす対戦順最適化
- `finance.html` / `accounting.html` — 現行の会計画面
- `todo.html` — ホームとコーチ専用フォルダで共有するタスク
- `diagnostics.html` — この端末の通信・PWA・直近20件のJavaScriptエラー確認
- `usage-counter.js` — 個人情報を送らない月別・機能別の匿名利用カウンター
- `calendar-attendance.js` — カレンダー内の調整さんURL抽出と保護者向けLINE文の生成

全ページの一覧は `index.html` と `coach.html` の導線を基準にしてください。

ヘッダーとフッターは各HTMLに空のマウント先だけを置き、`common.js`から一元生成します。アイコンは、チームロゴをブランド表示に、絵文字を共通サイズの機能アイコンに限定して使い分けます。

横長の一覧表は、`mobile-stack`クラスを付けると画面幅640px以下でカード表示へ切り替わります。列見出しは`common.js`が各セルへ自動設定します。編集項目が多い表は横スクロールを維持し、操作列を固定します。

スマートフォンでは、入力欄の文字を16px以上、主要なボタンの高さを44px以上にします。iOS Safariは入力欄の文字が16px未満だとタップ時に画面を自動拡大し、横スクロールやレイアウト崩れの原因になるためです。指定は`@media (pointer: coarse)`の中だけに置き、パソコン表示は従来のままにしています。選択肢はネイティブの選択画面が開くため対象外にして、表の列幅を保ちます。

試合調整表はスマホ幅では日程を1列ずつ表示します。「表示する日程」または左右ボタンで切り替え、チーム名・状態・担当者を同じ画面内で確認します。パソコン幅では全日程の横長一覧を表示します。

試合調整の日程から開く「大会任務分担」「大会要項・対戦表」「会計・決算書」は、日程IDで相互に連動します。コーチ専用フォルダの「立替・購入相談」「共有タスク」は、ホーム側と同じFirebase保存先を使用します。入口が違ってもデータは同一です。

対戦表は「対戦表を自動作成」で総当たりカードを作成し、同一チームの連続試合を最優先で回避します。「現在の順番を最適化」では対戦カードを変えずに順番だけを調整します。固定した試合はその枠を維持し、結果欄で連続試合数とチーム別の最短休憩を確認できます。LINE案内文は大会要綱・対戦表の入力を再利用し、対戦依頼・参加確定後・リマインドの3種類を送信前に編集してコピーできます。

チームカレンダーでは、今後90日間の予定の説明欄・場所・URL関連項目に登録された `https://chouseisan.com/` のURLを自動抽出します。該当予定がある場合、カレンダーには件数と「出欠確認・参加案内」への入口だけを表示します。タイトル・日付・調整さんURLの一覧と、保護者向けLINE文の一括コピーは「出欠確認・参加案内」ページにまとめています。アプリからLINEへ自動送信はせず、公式LINE等の配信画面へ貼り付けて利用します。URLや案内文はFirebaseへ保存しません。

## データ保存

通常の入力内容は端末内にも保存し、その後Firebaseへ同期します。団員名簿は個人情報を端末に残さないため、`members_v2/{団員ID}`へ直接クラウド保存します。名簿の追加・修正・削除は団員単位で行われます。

画面の保存通知は次の状態を区別します。

- クラウド保存完了
- 端末内のみ保存
- クラウド再接続待ち
- 保存失敗

Firebase接続前の空データを自動でクラウドへ書き戻さない設計です。運用前と大きな変更の前には、Firebase Consoleからバックアップを取得してください。

### 匿名の利用状況

どの機能がよく使われているかを確認するため、`usage_stats_v1/{YYYY-MM}/{機能キー}`へ月別の利用回数だけを加算します。送信する値は固定された機能キーと回数だけで、氏名、入力内容、チーム名、URLパラメータ、端末ID、ユーザーIDは保存しません。同一機能は同じブラウザセッション内で1回として数え、LINEコピー・対戦表作成・対戦表最適化・LINE案内作成は操作回数を集計します。

集計結果は、コーチ専用フォルダの「動作診断」→「匿名の利用状況」で月別に確認できます。数字は個人や正確な利用者数ではなく、機能改善のための利用傾向です。既存データの保存先と構造は変更しません。

## セキュリティ上の前提

GitHub Pages上のHTML・JavaScriptは誰でも閲覧できます。次の情報をソースへ直接書かないでください。

- パスワード、固定パスコード、秘密鍵
- 団員名簿や保護者名などの個人情報
- 限定共有URL

現在はLINEのリッチメニュー等からすぐ利用できることを優先し、Firebase Authenticationを使用しない公開モードです。Firebase本番環境のルールはリポジトリへ含めず、Firebase Console側で管理します。管理系ページには`noindex,nofollow`を設定していますが、これは検索結果への掲載を抑える指定であり、アクセス制限ではありません。

ログインなしのクラウド編集を利用するには、Firebase本番環境でアプリが使用する保存先への読み取り・書き込みを許可する必要があります。データベース全体を無条件に公開せず、使用する保存先と入力形式を確認したうえで設定してください。

URLを知っている人は名簿・会計などを閲覧・変更・削除できます。運用時はURLの共有範囲を限定し、Firebaseのバックアップを定期的に取得してください。将来必要になった場合は、閲覧はそのまま、編集だけ認証する方式へ変更できます。

アカウント管理画面にはパスワードを保存しません。認証情報は管理者のパスワード管理ツールで管理してください。

## PWA・更新

Service Workerは公開ページと共通アセットを事前キャッシュし、閲覧済みページをオフライン時の候補として保存します。管理系ページは事前キャッシュしません。

リリース時は、次のバージョンを同じ値に更新してください。

- `index.html` の `meta[name="app-version"]`
- `tournament.html` の `meta[name="app-version"]`
- `sw.js` の `APP_VERSION`

`package.json` のバージョンは、PWAバージョン `YYYYMMDD-N` を `YYYYMMDD.N.0` に直した値へ合わせます。例：`20260719-7` の場合は `20260719.7.0` です。

## 旧ページ

互換性と既存ブックマークのため残していますが、検索対象外にしています。

- `album.html` — 旧アルバム案内
- `kaikei.html` — 旧会計・立替画面（印刷対応のみ保守）
- `heat.html` — 旧熱中症画面。現行は `weather.html`
- `init-data.html` — 廃止済み。データ上書き機能はありません

## ローカル確認

Service Workerを含めて確認するため、ファイルを直接開かずHTTPサーバーを使用します。

```bash
python3 -m http.server 8000
```

別のターミナルで自動検査を実行します。

```bash
npm test
```

検査内容はローカルリンク、重複ID、JavaScript構文、PWAバージョン、事前キャッシュ対象、危険なキャッシュ削除、既知の秘密情報形式、スマートフォンの入力欄16px下限とタップ領域44px、匿名カウンターが個人情報を送らないことです。GitHub Actionsでも同じ検査を実行します。

画面上の問題調査は、コーチ画面の「動作診断」から端末内エラーログを確認できます。ログは外部へ自動送信されないため、複数端末を横断する監視が必要な場合は、認証と個人情報の除外方針を決めたうえで専用監視サービスを導入してください。
